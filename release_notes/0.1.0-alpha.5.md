# scry 0.1.0-alpha.5

A profile can now read the widths games actually store: 8-, 16- and 64-bit
integers, signed and unsigned, and booleans.

## New value types

`type` now accepts `i8`, `u8`, `i16`, `u16`, `i64` and `bool`, alongside `i32`,
`u32`, `u64`, `f32` and `string`. They work everywhere a type does: scalar
watches, record fields, collection elements, and the output of a `derived`
watch.

```json
{ "tier": "tier1", "name": "level", "module": "game.exe",
  "offsets": ["0x1A2B3C", "0x58"], "type": "u8" }
```

Until now a one-byte level or a two-byte item ID had to be read as a `u32`,
which picked up the bytes next to it. The number looked right until those bytes
changed.

On the wire each is a plain JSON number, except `bool`, which is `true` or
`false`. `scry schema` gives every integer type its own `minimum` and `maximum`,
and a `bool` is `"boolean"`.

## Booleans are strict

A `bool` is one byte: `0` is `false`, `1` is `true`, and **any other byte is
`unavailable`**. A byte of `2` or `0xFF` is a torn read or a field that is not a
flag, and reporting it as `true` would hide that. A game that treats any
non-zero byte as "on" should read the field as a `u8` and test it with
`ne: 0`.

The same goes for a `derived` watch typed `bool`: after truncation, the result
must be `0` or `1`.

In expressions a `bool` counts as the `0` or `1` it is stored as, so an `add`
over flags counts the ones that are set. A `where` clause tests a flag with a
JSON boolean:

```json
"where": [ { "field": "alive", "eq": true } ]
```

`eq` and `ne` only. A boolean literal tested against a field that is not a
`bool` is undecidable, so the fold is `unavailable`, as with a string against a
number.

## For code that links the crate

`Value` gains the variants `I8`, `U8`, `I16`, `U16`, `I64` and `Bool`, and
`ValueType` the matching ones. `Literal` gains `Bool`. A `match` over any of
them without a wildcard arm needs the new arms.

## Known limits

- **Expressions evaluate in `f64`.** An `i64` or `u64` above 2^53 loses
  precision on its way through a `derived` watch. Read directly, it is exact.
- **64-bit reader, 32-bit game is still unproven against a real game.** CI
  proves 64→64 and 32→32.
- **No resync.** A line a host fails to read stays lost until the next change to
  that watch.
- **Windows is the target.** The Linux backend exists for development and CI.
- **The binaries are unsigned**, so SmartScreen will report an unknown publisher.
- **Nothing is stable yet.** Alpha means the JSON events, the profile schema and
  the CLI flags may all still change.
