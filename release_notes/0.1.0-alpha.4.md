# scry 0.1.0-alpha.4

Profiles now say which contract their values follow, a host can tell why scry
stopped, and a round of review fixes makes the engine stricter about what it
accepts and harder to knock over with memory it misreads.

## Contracts: what the values mean, apart from how they are read

A profile describes how to read one build of one game. What a client draws
depends on something else: which values exist, what they are called, and of what
type. That is the **contract**, and a new game patch normally means a new profile
under the same contract. `docs/contracts-and-views.md` sets out the split and who
owns each part.

A profile declares it with an id and a `major.minor` version:

```json
{ "label": "Sea of Stars (Steam)",
  "contract": { "id": "sea-of-stars", "version": "2.0" },
  "watches": [ … ] }
```

and `attached` reports it the same way, so a client picks its view by the
contract instead of the profile label. The integer `contractVersion` is still
accepted, marked deprecated, and `attached` keeps sending `contract_version` as
the major for hosts that read only that.

`scry schema <profile>` prints the JSON Schema of the values a profile produces.
It needs no game and runs on any platform, which is what lets a profile
repository check in CI that each profile really implements the contract it
claims.

## Why scry stopped

Every exit status is now documented in `--help` and the README, and in
`--format json` a known failure ends the stream with one last line:

```json
{ "event": "error", "code": "no_profile_fits", "message": "…", "exit_code": 3 }
```

The codes are `usage`, `no_such_process`, `profiles_unreadable`,
`attach_failed`, `no_profile_fits`, `resolver_failed` and `internal` (a panic).
A host can now tell "this game has no profile" from a crash without reading
stderr.

`watch` also notices when the game closes. It ends with `detached`, which now
carries a `reason` (`once`, `duration` or `target_exited`), and exits with the new
status 5. Before, a closed game left scry running and reporting every watch as
unavailable.

## Stricter profiles

These were accepted before and are now load errors, each naming the problem:

- **Two watches with the same name.** The value used to flip between them every
  tick.
- **A `rate_hz` outside 0.01–1000.** A tiny positive rate crashed the loop.
- **A collection `max` above 4096.** A garbage count could size an allocation of
  gigabytes, or a first line too long for a host to accept. The engine also
  clamps the count it reads.
- **A `derived` expression with more than one operator, or an unknown key.**
  `{"watch": "hp", "const": 1}` used to parse silently as a constant, and a typo
  in a fold was ignored.
- **Offsets like `"0x-5"`** and doubled signs.

`il2cpp2scry` refuses a static field used as an instance offset, and no longer
miscounts braces inside string literals.

## Fixes

- **A NaN is no longer re-sent every tick.** Floats compare by bit pattern, so
  torn or uninitialised memory reads as unchanged instead of as a new value 20
  times a second.
- **The process name is matched without regard to case**, as Windows treats it.
- **Profile choice is deterministic.** A profiles folder is read in file-name
  order, a profile whose `match.version` is confirmed wins over one that isn't,
  and scry warns on stderr, naming every candidate, when several fit.
- **A 64-bit scry finds the modules of a 32-bit game**, through
  `K32EnumProcessModulesEx`.
- **Re-attaching backs off** while nothing can be read, instead of rescanning
  the whole process every half second on a menu or loading screen.
- **A read that runs off the address space fails** instead of panicking.
- **Bad command lines are usage errors**: an unparseable or negative `--for`, and
  a flag with its value missing.

## Known limits

- **64-bit reader, 32-bit game is fixed but unproven against a real game.** CI
  proves 64→64 and 32→32; the mixed case compiles and uses the right API, and
  has not been run against a WOW64 game.
- **No resync.** A line a host fails to read stays lost until the next change to
  that watch.
- **Windows is the target.** The Linux backend exists for development and CI.
- **The binaries are unsigned**, so SmartScreen will report an unknown publisher.
- **Nothing is stable yet.** Alpha means the JSON events, the profile schema and
  the CLI flags may all still change.
