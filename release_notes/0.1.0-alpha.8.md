# scry 0.1.0-alpha.8

A collection of records can filter what it emits.

## `where` on a collection

Some containers are far larger than the part that matters. Final Fantasy VII
Rebirth keeps every location volume of the loaded world in one array, over four
hundred of them, and each has a state byte that is non-zero while the player
stands inside it. The player is in a handful at a time.

A record collection now takes the same flat `where` clauses a fold does (`eq`,
`ne`, `lt`, `le`, `gt`, `ge`, all of which must hold). It emits only the
elements that pass, in their original order:

```json
{ "tier": "collection", "name": "locations",
  "base": { "tier": "tier1", "module": "ff7rebirth_.exe", "offsets": ["0x91D84C0", "0x8"] },
  "count": ["0x8"], "items": ["0x0"], "stride": 8, "element": [0, 0],
  "fields": {
    "state": { "offsets": ["0x2A0"], "type": "u8" },
    "kind":  { "offsets": ["0x27C"], "type": "u8" },
    "id":    { "offsets": ["0x270"], "type": { "string": "fname" } }
  },
  "where": [ { "field": "state", "ne": 0 }, { "field": "kind", "eq": 0 } ],
  "max": 1024 }
```

Every element is still read: `max` caps how many are read, not how many are
emitted. If an element's test cannot be decided, because a field could not be
read or text was tested against a number, the element stays in place as
`unavailable`. It is not dropped, and the list does not fail. When the profile
loads, each clause must name one of the collection's `fields`, and a scalar
collection cannot take `where`.
